# 三个关键问题的完整分析与方案

## 问题 1：路由优先级如何映射到 Agent 特性

### T0 - 策略路由 (Policy Based Routing) → Agent 策略规则

| 网络路由概念 | 对应 Agent 系统 | 实现方式 |
|------------|---------------|---------|
| 策略路由条件 | 任务特征条件 | `AgentPolicy.Condition(task)` |
| 策略优先级 | 策略执行顺序 | `AgentPolicy.Priority` |
| 下一跳 | 目标 Agent | `AgentPolicy.TargetAgent` |

**策略示例：**
```go
Policy { 
    PolicyName: "EmergencySecurity",
    Condition: func(task string) bool { 
        return strings.Contains(task, "critical") || 
               strings.Contains(task, "emergency") 
    },
    TargetAgent: "Pentesting",
    Priority: 1 
}
```

---

### T1 - 掩码长度 (Prefix Length) → 匹配精准度

| 网络路由概念 | 对应 Agent 系统 | 说明 |
|------------|---------------|------|
| /0 (默认路由) | 通用 Agent | 没有具体匹配时的兜底 |
| /8 (大类) | 领域 Agent | "security", "code" 等 |
| /16 (小类) | 功能 Agent | "sql", "xss" |
| /24 (精准) | 专用 Agent | "SQL注入" |

---

### T2 - 管理距离 (Administrative Distance) → Agent 信任度

| AD 值 | 含义 | 对应 Agent |
|------|------|---------|
| 1 | 手动指定 (最高) | 用户明确指定的 Agent |
| 5 | 完美学习 | 成功率 ≥95% |
| 10 | 默认专用 | 专门用途 Agent |
| 20 | 良好学习 | 成功率 ≥85% |
| 50 | 默认通用 | 一般用途 |
| 255 | 最后选择 | Generic Agent |

---

### T3 - Metric (计算距离) → 综合性能评分

| 网络路由概念 | 对应 Agent 特性 | 计算方式 | 权重 |
|------------|---------------|---------|------|
| 跳数 | 历史成功率 | `(1.0 - SuccessRate) * 100` | 40% |
| 带宽 | 最近成功率 | `(1.0 - RecentSuccess) * 100` | 30% |
| 延迟 | 执行时间 | `Normalized(ExecTime)` | 20% |
| 负载 | 稳定性方差 | `QualityVariance` | 10% |
| 默认值 | 基础度量 | `BaseMetric` | 10% |

### 多特征权衡方案

**问题：** 多一个错误特性 vs 少一个重要特性，哪个更好？

| 场景 | 判断标准 | 决策 |
|------|---------|-----|
| 情况 A: 一个致命特性缺失 | 任务完成率为 0% | ❌ 绝对不可 |
| 情况 B: 一个重要特性缺失 | 成功率下降 30% | ⚠️ 有风险 |
| 情况 C: 有一些非必要的错误特性 | 成功率下降 5% | ✅ 可以接受 |

**解决算法：**
```
1. 检查关键特性（硬约束）
   if (missingCriticalFeature):
       淘汰这个 Agent

2. 计算质量损失
   QualityLoss = Sum(importantFeatureMissing * penalty)
                 + Sum(wrongFeaturePresent * smallPenalty)

3. 选择质量损失最小的
```

---

### Metric 计算公式

```
CompositeMetric = 
    (历史成功率因子 × 0.4) +
    (近期成功率因子 × 0.3) +
    (执行时间因子 × 0.2) +
    (稳定性因子 × 0.1) +
    (基础度量 × 0.1)

其中：
  - 成功率因子 = (1.0 - SuccessRate) × 100
  - 时间因子 = Normalize(ExecutionTime)
  - 稳定性因子 = QualityVariance × 100
```

## 问题 3：何时增删 Agent、修改特性

### 增删改的触发条件

#### 一、何时新增路由/Agent

| 触发信号 | 说明 | 行动 |
|---------|------|------|
| 发现成功的新模式 | Intent/Planner 发现新规律 | `RegisterRoute(newPattern, newAgent)` |
| Generic Agent 高频成功 | 某类任务 Generic 成功率很高 | 创建新专门 Agent |
| 用户持续成功反馈 | 用户对结果满意 | 学习和巩固 |

**具体条件：**
```
if (Generic.Agent.SuccessRate > 0.8 
    AND RecentHits > 10 
    AND TaskPattern.Stable):
    CreateSpecializedAgent()
```

---

#### 二、何时删除路由/Agent

| 触发信号 | 说明 | 行动 |
|---------|------|------|
| 长期低成功率 | <30% AND >20 次执行 | 考虑删除 |
| 有更好替代 | 更精确路由已经存在且更好 | 删除旧路由 |
| 维护成本 > 收益 | 极少使用且维护麻烦 | 移除 |

**具体条件：**
```
if (Route.SuccessRate < 0.3 
    AND TotalExecutions > 20 
    AND HasBetterAlternative):
    MarkForDeletion()
```

---

#### 三、何时修改 Agent 特性

| 触发信号 | 修改内容 |
|---------|---------|
| 连续成功 | 提高 `Reliability`，降低 `AdminDistance` |
| 连续失败 | 降低 `Reliability`，提高 `AdminDistance` |
| 新技能掌握 | 更新 `Skills` Map |
| 性能变化 | 更新 `BaseMetric` |

**学习触发周期：**
- 每 5 次执行后调整小特性
- 每 20 次执行后评估大调整
- 每 100 次执行后重新归档
